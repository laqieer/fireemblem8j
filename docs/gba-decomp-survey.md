# GBA Decompilation Survey: Techniques FE8J Can Adopt

**Purpose.** This is a survey of the GBA-decompilation ecosystem — the pret Pokémon family, the Fire Emblem decomp lineage, other GBA game decomps, and the shared matching/tooling infrastructure — undertaken to find concrete techniques the FE8J project (byte-perfect decomp of the Fire Emblem 8 *Japanese* ROM, oracle `make compare`) can adopt or learn from. FE8J's core challenge is **cross-region matching**: most JP code and data is region-different vs the near-complete US decomp (`../fireemblem8u`), so the survey is filtered for what helps cross-region triage, ARM/Thumb disasm→C bootstrap, agbcc byte-matching, progress/verify infrastructure, and contributor workflow. FE8J's data front is byte-complete and the code front sits at roughly 25% C; the rest is region-different functions we are now mechanizing via the gbadisasm bootstrap (D23).

## What FE8J already uses (baseline)

So readers know what is *not* new:

- **Compiler / build:** agbcc (GCC 2.95, C89-era) at `tools/agbcc`; arm-none-eabi binutils; `make compare` as the sha1 oracle against `baserom.gba`.
- **RE tools:** IDA Pro 9.3 + Hex-Rays (MCP), Ghidra (pyghidra-mcp), decomp-permuter (upstream ARM32, plus the owner's `laqieer/decomp-permuter-arm` fork).
- **Matching:** asm-differ, objdiff (3.7.2 vendored), m2c (arch_arm), coddog, mizuchi (piloted, D12), decomp.me.
- **Disasm bootstrap:** gbadisasm (laqieer fork in `tools/gbadisasm`, with `fireemblem8.cfg`/`fireemblem8_ida.cfg` auto-generated from an IDA DB) — adopted D23 to mechanically emit build-ready descriptive asm for region-different functions.
- **Progress:** frogress + decomp.dev trackers (FE8J ≈ 20% there).
- **Carving:** custom `gen_layout.py` / `calcprogress.py` / ldscript split-the-incbin pipeline; a conflict-free parallel-carving system (per-task fragments + serial integrator, D13/D14); FEBuilder ROM-def map ingested (D15).

## Findings by category

### pret / Pokémon GBA decomps

pret is the gold-standard org for FE8J's exact stack (GBA + agbcc + sha1-against-baserom). Its conventions transfer almost 1:1, and one repo — `pokeemerald-jp` — is a direct precedent for FE8J's separate-repo JP-port architecture.

| --- | --- | --- | --- |
| [pokeemerald-jp](https://github.com/pret/pokeemerald-jp) | Standalone JP decomp, separate repo from English pokeemerald, own `baserom_jp.gba` + sha1, same agbcc + `make compare` | Direct precedent that the **separate-repo JP-port model** (FE8J's choice) is the established pret pattern, not an outlier. | [gbadisasm](https://github.com/camthesaxman/gbadisasm) | The bootstrap disassembler; `.cfg` of arm/thumb func hints → build-ready asm | Cross-check, not new work — confirms FE8J (D23) is on the canonical pret bootstrap path. Periodically pull upstream/fork fixes (e.g. Icedude907's better label/data handling) since data-vs-code disambiguation is FE8J's hard part. | cross-check |
| [pret INSTALL conventions](https://github.com/pret/pokeemerald/blob/master/INSTALL.md) | agbcc install.sh, `make compare`, `make modern`, `make -j` | Mostly already matched. Concrete borrowables: `tools/` (scaninc, preproc+charmap), the Thumb-filtered m2c+permuter loop, and a CI symbols branch.

## Cross-region techniques to apply now

These build directly on the gbadisasm bootstrap (D23) to attack the remaining region-different **code** front (code ~25% → up).

1. **Classify before carving — coddog as the region-same/different oracle.** Run [coddog](https://github.com/ethteck/coddog) over `fireemblem8u.elf` + the JP ROM/ELF. Hash-matches are region-SAME → port the US `.c` unchanged via the function library's address. Present-but-not-matching → region-DIFFERENT, queue for the pipeline below. Near-matches flag pointer/literal-pool-only deltas (pure relocation, no real work). This turns the strategy's step-1 pattern search into a maintained, scored classifier and gives a CI gate that re-confirms which TUs are still safe to port. Augments, doesn't replace, `match_us_jp.py`.

2. **Bootstrap → C first pass: gbadisasm → m2c → agbcc.** For each region-different Thumb function, feed the gbadisasm-emitted descriptive asm to [m2c (arch_arm)](https://github.com/matt-kempster/m2c) with a single project-wide `ctx.c` generated from fireemblem8u headers. m2c output preserves the JP instruction structure, so it compiles closer to matching than Hex-Rays/Ghidra C. **Filter to Thumb functions with a buildable context first** (pret's discipline) — automate the easy wins, hold ARM/region-different-scheduling funcs for hand work.

3. **Diff against US, not just baserom.** Point [asm-differ](https://github.com/simonlindholm/asm-differ) (and [objdiff](https://github.com/encounter/objdiff)'s relocation-aware two-target mode) at the **US compiled `.o`** from fireemblem8u's ELF. The diff then tells you per-function whether the divergence is literal-pool words only (relocation, auto-fixed at link — effectively region-same, just relinked) or real codegen (genuine region-different logic). This is the single most informative reframing: "what is the region delta from US?" instead of "does it match JP?". Requires producing **per-TU target objects** ([splat](https://github.com/ethteck/splat)'s pattern) so objdiff has a base to diff against — the input D12 flagged missing.

4. **agbcc near-miss checklist before the permuter.** When a function is 1–2 instructions off, run the [documented agbcc-quirk checklist](https://github.com/Dream-Atelier/kl-eod-decomp) first: (a) first-literal-pool load in **r2 vs r3** (old vs modern agbcc — check which variant built that JP subsystem; the agbcc forks `jiangzhengwenjz/new_newlib_pret`, `luckytyphlosion/new_layout_with_libs`, Klonoa's `-ftst` are the fallbacks); (b) `-fprologue-bugfix` flipping leaf-function LR saves; (c) `-ftst` controlling `tst` vs `cmp #0`; (d) remember agbcc emits `bl` (not `bx`) for long intra-function branches — not region-different behavior. Most "almost-matching" near-misses are one of these, not a logic error.

5. **Permute the last mile, outside the sandbox.** For functions that are logic-correct but 1–5 instructions off after m2c, use [decomp-permuter-arm](https://github.com/laqieer/decomp-permuter-arm) with `PERM_*` macros + randomization (the "nonsensical change that fixes regalloc by accident"). Verify the vendored upstream tree has the ARM import pattern + agbcc config, or fold in the owner's fork. Borrow [tmc-permuter](https://github.com/octorock/tmc-permuter)'s `import.py` automation (carved asm → ready permuter dir) and its worker/Docker model to run long permutations **outside** the SIGTERM-happy sandbox (the D9/D12 pain point).

6. **Ship WIP C without regressing `make compare` — the NONMATCH fallback.** Adopt [Sonic Advance 2](https://github.com/SAT-R/sa2)'s `NONMATCH` macro + `asm/non_matching/*.inc` pattern: a function whose C isn't byte-matching yet falls back to the original carved asm, so the ROM still matches while the C is iterated and committed. This is the key unblock for the autonomous loop — region-different C can be committed as work-in-progress without ever breaking the oracle.

7. **When there's no clean byte match — BinDiff/Diaphora correspondence.** Reuse the FE-proven [function-match pipeline](https://github.com/laqieer/FE_GBA_Function_Library/tree/master/function%20match): run Diaphora/BinDiff between the FE8U ELF and the JP ROM (or the IDA DBs FE8J already has) to get a candidate FE8U-symbol correspondence + similarity score for a function that pattern-search misses, then port + permute. `merge_match_results.py` combines engine outputs.

8. **Borrow the JP solution from a sibling, not the US version.** For JP-specific categories (text rendering, glyph handling, menu geometry, save versioning) where FE8J diverges from FE8U, the JP solution likely already exists in [fe7 (JP)](https://github.com/FireEmblemUniverse/fireemblem6j) or fe6 on the shared engine — port across FE6/FE7/FE8 JP rather than fighting the US version.
