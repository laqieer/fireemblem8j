# m2c — asm → C decompiler (seed C for region-different functions)

[`m2c`](https://github.com/matt-kempster/m2c) ("*machine code to C*", formerly
`mips_to_c`) turns GNU `as` assembly into C, with a focus on producing
**matching-oriented** C — source that recompiles to byte-identical code. That is
exactly what we need: for FE8J functions whose machine code differs from the US
ROM, m2c gives us a **seed C** starting point that we then refine with the AI /
[`decomp-permuter`](../reverse-engineering.md) loop until `make compare` is `OK`.

Unlike IDA/Ghidra (which aim for *readable* C), m2c aims for *re-compilable,
matching* C, and is designed to plug into decomp pipelines alongside
`asm-differ` and `decomp-permuter`.

## Why it fits FE8J: GBA / ARM / Thumb support

m2c supports MIPS, ARM, and PowerPC. The **`gba`** target is precisely the
GBA ARM/Thumb + APCS ABI that FE8 uses (ARM7TDMI, agbcc-compiled). Evidence in
the upstream source (paths relative to `tools/m2c/` after setup):

- **GBA target is a first-class platform.** `m2c/options.py` defines
  `PlatformEnum.GBA = "gba"`, and its `.arch` maps to `ArchEnum.ARM`. `m2c.py
  --help` lists `gba` among the supported platforms.
- **A dedicated GBA arch class.** `m2c/arch_arm.py` (~line 2046):
  ```python
  class ArmGbaArch(ArmArch):
      """Arch variant that follows the APCS ABI used on Gameboy Advance."""
      base_struct_align = 4
  ```
  This is the APCS ABI agbcc targets — the same ABI FE8J's `tools/agbcc`
  pipeline uses.
- **Thumb is handled natively.** `ArmArch` in `m2c/arch_arm.py` understands
  Thumb mode: it tracks `asm_state.is_thumb` (e.g. the pre-UAL `.syntax
  unified` check around line 1072, the `cbz`/`cbnz` "Thumb conditional branch"
  at ~line 1219, MWCC Thumb switch detection at ~line 501, and Thumb long-branch
  veneers at ~line 927). It parses `.code 16` / `.thumb_func` directives that
  agbcc emits.
- **m2c ships agbcc/Thumb end-to-end tests.** Many tests under
  `tools/m2c/tests/end_to_end/*/agbcc-o2.s` are real Thumb assembly produced by
  `gcc 2.9-arm-000512` (i.e. agbcc), decompiled with `--target gba`. Example
  header from `store-casts/agbcc-o2.s`:
  ```
  @ Generated by gcc 2.9-arm-000512 for Thumb/elf
      .code   16
      ...
      .thumb_func
  test:
  ```

So the same compiler family and ABI we compile *with* is a compiler m2c
decompiles *from*.

## Install

```bash
scripts/tools/m2c/setup.sh
```

This clones upstream into `tools/m2c` (gitignored, like `tools/agbcc` and
`tools/decomp-permuter`) and creates a uv venv at `$HOME/m2c-venv` (override
with `M2C_VENV=...`). m2c is **mostly pure Python**: `pycparser` is vendored as
`m2c_pycparser`, so the only third-party *Python* runtime dependency is the
`graphviz` package (used only by `--visualize`). The setup is idempotent —
re-run it to update m2c.

> The seed→C workflow below needs none of this — only `--visualize` does. That
> flag also needs the **system Graphviz** `dot` binary on `PATH` (e.g.
> `apt-get install graphviz`); the setup script installs only the Python
> binding, not the system package. If you don't use `--visualize` you can ignore
> Graphviz entirely.

The setup finishes by running a smoke test (m2c on a bundled agbcc/Thumb
function) so a fresh install proves the GBA target works end to end.

## The wrapper

```bash
scripts/tools/m2c/m2c.sh [m2c options] <asmfile>...
```

It just does `exec python3 tools/m2c/m2c.py --target gba "$@"` using the venv
python, so every upstream flag is available. Useful ones:

- `--context <ctx.c>` — a C file of struct/typedef/prototype context. Caching is
  per-context (cache stored next to the file as `*.m2c`); add `--no-cache` to
  disable.
- `-f <FuncName>` — decompile only the named function (default: all functions in
  the `.text` of the input).
- `--globals=all|used|none` — control emission of global declarations /
  initializers from `data`/`rodata`/`bss` sections.
- `--stack-structs` — emit the inferred `struct _m2c_stack_<fn>` so you can name
  stack locals and feed it back via `--context`.

## FE8J workflow: region-different function → seed C

When a function's machine code differs between the US and JP ROMs (so we can't
just relink US source), use m2c to bootstrap the JP version:

1. **Find the function's JP address** (see `docs/strategy.md` /
   `scripts/match_us_jp.py` / the IDA & Ghidra workflows in
   `docs/reverse-engineering.md`). Note start/end addresses.

2. **Dump its assembly** from the built ELF. m2c wants GNU `as` syntax — labels
   plus mnemonics, no raw bytes. `arm-none-eabi-objdump -d` gets close; pass
   `--no-show-raw-insn` to drop the opcode column (you may still need to trim the
   leading `address:` column / objdump header so m2c sees clean `label:` +
   instruction lines):
   ```bash
   arm-none-eabi-objdump -d --no-show-raw-insn \
     --start-address=0x080XXXXX --stop-address=0x080YYYYY \
     fireemblem8.elf > /tmp/fn.s
   ```
   (For a whole `.text` section, run `arm-none-eabi-objdump -d
   fireemblem8.elf` and let m2c pick functions with `-f`. In practice the
   cleanest input is the same `as`-syntax asm our split workflow already
   produces — see `asm/` and `docs/strategy.md`.)

3. **Decompile to seed C:**
   ```bash
   scripts/tools/m2c/m2c.sh -f SomeFunc /tmp/fn.s > /tmp/SomeFunc_seed.c
   ```
   Add `--context` with a small header of the structs/types the function touches
   to get typed args/fields instead of `unkNN` placeholders.

4. **Refine the seed.** m2c output is a *starting point*, not final source.
   Port it into `src/`, adjust to FE8J conventions (`#include "global.h"`,
   PascalCase, `/* 0C */` field offsets), and iterate with the AI /
   `decomp-permuter` loop. **`make compare` is the oracle** — keep iterating
   until the function matches and `make compare` stays `OK`.

> Note: `fireemblem8.elf` is a build artifact (gitignored). Build it first
> (`make`) so the objdump step has an ELF to read.

## Worked example (bundled agbcc/Thumb test)

Input — `tools/m2c/tests/end_to_end/store-casts/agbcc-o2.s` (real Thumb from
agbcc, `.code 16` / `.thumb_func`):

```
$ scripts/tools/m2c/m2c.sh tools/m2c/tests/end_to_end/store-casts/agbcc-o2.s
void test(void *arg0, s16 arg1, u16 arg2) {
    u16 temp_r2;

    temp_r2 = arg2;
    arg0->unk8 = 2;
    arg0->unkA = arg1;
    arg0->unkC = temp_r2;
    arg0->unkE = (s16) ((s16) temp_r2 + arg1);
}
```

Minimal hand-written Thumb function (the shape of an objdump dump):

```
$ cat /tmp/fe8_demo.s
	.code 16
	.thumb_func
	.globl SumThree
SumThree:
	add	r0, r0, r1
	add	r0, r0, r2
	bx	lr

$ scripts/tools/m2c/m2c.sh /tmp/fe8_demo.s
s32 SumThree(s32 arg0, s32 arg1, s32 arg2) {
    return arg0 + arg1 + arg2;
}
```

Both confirm the GBA Thumb pipeline works: with `--target gba`, m2c parses
`.code 16` / `.thumb_func` assembly and emits compilable seed C.

## Limitations to expect

- Output is **matching-oriented, not pretty** — expect `unkNN` fields, `tempXX`
  locals, casts, and sometimes suboptimal loops. That's fine: it's a seed.
- Without `--context`, types are guessed (`void *`, `s32`, `unkNN`). Supplying
  context dramatically improves the seed.
- m2c can't generate initializers for bitfield structs or symbols whose type it
  can't infer; provide types via `--context` for those.
